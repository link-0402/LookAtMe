# TargetMe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Dalamud API 15 plugin that lists who is targeting your character. It covers everything Peeping Tim does and adds a header-less list, emote chips, a hover overlay in the world, a tell that's readied in the chat input, and TargetZoom-style camera focus.

**Architecture:** Pure logic lives in `TargetMe/Core` (no Dalamud references) and is unit-tested by linking its files into `TargetMe.Tests`. Game-facing units (tracker, emote hook, actions, camera, alerts, IPC) and ImGui windows are built on top. `Plugin.cs` is the composition root.

**Tech Stack:** C# / `Dalamud.NET.Sdk/15.0.0` (net10.0), FFXIVClientStructs and Lumina (bundled with Dalamud), NAudio 2.2.1, xUnit v3.

**Spec:** `docs/superpowers/specs/2026-10-16-targetme-design.md`. Read it before any task: it fixes the exact behaviour, defaults and copy.

## Global Constraints

- SDK `Dalamud.NET.Sdk/15.0.0`; InternalName `TargetMe`; display name `TargetMe`; author `Luci`.
- No ECommons. Use Dalamud services directly (`[PluginService]` statics in `Services.cs`).
- Commands: `/targetme` (toggle window), `/targetme settings`, `/targetme move`, `/targetme stop`.
- Viewer key: `Name@HomeWorldId` (world row id, not world name).
- Defaults: list cap 15; background opacity 0.75; emote chip lifetime 15 s (0 = session), 2 s fade, max 5 chips per row; overlay colour `#FF4FA3`; ring radius 0.7 yalms; camera zoom distance 4 yalms; tracker refresh of loaded state every 100 ms.
- Optional IPC features (Moodles, CrystalSync) never print to chat when missing; they hide themselves.
- Every hook is created in try/catch; a failure disables only that feature and logs a warning.
- Game memory and agent calls happen on the framework thread only.
- In-game checks use XIV Bridge only for client-side queries/UI; they never send chat or act in the world for the player. Tests run in an inn room with automation on (bridge rule).
- Commit after every task with a `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` trailer. Write commit messages to a file and use `git commit -F` (Bash backslash rule in the user's CLAUDE.md).

## Review Focus

1. **Same name, different worlds** (cross-world visitors). They must be two separate rows. Pinned by `ViewerListTests.SameNameDifferentWorldsAreDistinct` (Task 2).
2. **Viewer unloads while hovered or while the camera is focused on them.** The overlay must skip them and the camera must stop and restore, with no stale address dereferenced. Pinned by `CameraFocus` reacquiring the object by id every frame (Task 8, step 3) and `ViewerRow` using `IsLoaded` (Task 4). Checked in game in Task 11.
3. **Plugin unloads mid camera focus.** The camera must be restored before the hooks are disposed. The dispose order is fixed in Task 8, step 4, and checked in Task 11.
4. **Esc pressed while typing in chat** must not stop the camera focus. Pinned by `EscGateTests` (Task 8).
5. **Busy areas (100+ players).** The list stays capped, and the scan runs once per frame with no allocations per player beyond new records. Pinned by `ViewerListTests.CapsToMostRecent` (Task 2); the scan design is in Task 3.

**Interfaces:**
- Produces:
  - `sealed class ViewerRecord { string Name; uint WorldId; string WorldName; ulong ContentId; string Key {get;} /* $"{Name}@{WorldId}" */; bool IsTargeting; bool IsLoaded; ulong GameObjectId; DateTime FirstSeen; DateTime LastSeen; EmoteChips Emotes; static string MakeKey(string name, uint worldId) }`
  - `static class ViewerList { IReadOnlyList<ViewerRecord> Visible(IEnumerable<ViewerRecord> all, int cap) }` sorts by targeting now first, then `LastSeen` descending, and caps at `max(cap,1)`.
  - `sealed class EmoteChips { void Add(ushort emoteId, DateTime now); IReadOnlyList<EmoteChip> Live(DateTime now, int lifetimeSeconds); }` and `record EmoteChip(ushort EmoteId, int Count, DateTime LastAt)`, plus `static float EmoteChips.Alpha(EmoteChip c, DateTime now, int lifetimeSeconds)`. The limit is 5 chips with the oldest dropping first. Adding an emote that already has a chip increments its Count, refreshes `LastAt` and moves it to the newest position. `lifetimeSeconds == 0` means the chip never expires and has alpha 1.
  - `sealed class Cooldowns { bool TryFire(string key, DateTime now, TimeSpan cooldown) }`
  - `static class RelativeTime { string Format(TimeSpan ago) }` returns `"now"` under 5 s, `"{s}s"` under 60 s, `"{m}m"` under 60 min, and `"{h}h"` otherwise.

**Files:**
- Create: `TargetMe/Tracking/ViewerTracker.cs`

**Interfaces:**

- [ ] **Step 1:** Implement `Update()`. Return early if `ObjectTable.LocalPlayer` is null. Loop over `ObjectTable` once, players only:
  - For each `IPlayerCharacter pc` (not the local player), look up its record by key.
  - If `pc.TargetObjectId == local.GameObjectId`: get or create the record. Fill `ContentId` from `((Character*)pc.Address)->ContentId` and `WorldName` from the Lumina `World` sheet. Set `IsTargeting=true` and `LastSeen=now`. Raise `ViewerStarted` if it wasn't targeting before.
  - For every record you see, set `IsLoaded=true` and `GameObjectId`.
  - Afterwards, any record not seen this frame gets `IsTargeting=false`, and `IsLoaded=false` if it wasn't seen in the loop. Throttle the `IsLoaded` refresh to every 100 ms, but evaluate targeting every frame.
- [ ] **Step 2:** `AddEmote` gets or creates the record (setting `IsTargeting=true` and `LastSeen=now`) and calls `record.Emotes.Add(emoteId, DateTime.Now)`. `Resolve` returns `ObjectTable.SearchById(r.GameObjectId) as IPlayerCharacter` when `IsLoaded` is true and the name matches, and null otherwise.
